## Duplicate-logic check on every pull request

`scripts/dupscan.mjs` runs in the `architecture` job of `.github/workflows/pr.yml` (pull request and merge queue). It finds copies of code with jscpd (pinned devDependency) and lines that match the formula rules (driver-count scaling, resonance, dB, air, unit factors, maths in `packages/ui`), and exits 1 on any finding not listed in `scripts/dupscan-allow.json`. A new copy of a formula therefore fails the pull request until the copy is removed (call the engine instead); the list itself only shrinks (T934, below). Findings that existed on 18 Nov 2026 are the baseline, each with reason "baseline 2026-11-18 (QO946.c256)" (John, 18 Nov 2026, "yes" to making the scan a check on every pull request). Test: `bash scripts/test/dupscan.test.sh`.

`scripts/dupscan-allow.json` is a gate file (listed in `GATE_FILES` in `land.conf`, John 18 Nov 2026, board item QO948: a pull request that changes it is refused unless its task has `gates_approved: QO<n>` for a board item John answered): a key added to it needs a `reason` that quotes a John ruling. Agents never add keys on their own and never regenerate it with `--write-baseline` (standing rule "No agent weakens anything on its own"). A key is never removed. When a copy is consolidated into the engine, its entry stays and is marked resolved: `"resolved": true, "resolved_to": "<engine file>:<function>", "resolved_by": "<task id>", "ruling": "QO949"` (John, QO949, 18 Nov 2026: "old entries stay, marked 'resolved, resolved to <engine function> by T902'; a resolved copy that reappears fails; T902 and future consolidations recorded so"). A resolved key never allows its copy: if it reappears the check fails and names the function to call. An allowed entry whose copy is gone fails the check until it is marked resolved (T911).

Homes and the ratchet (T934; John, 19 Nov 2026: "why wasn't the consolidation finished - our guard rail isn't working / remove the dupe and fix the guardrail"). Each kind of sum names its home in `scripts/dupscan-homes.json`: one engine declaration (`file:name`, a function, const or class member; never a whole file), found by its exact name with the TypeScript parser. For example every scaling by the driver count lives in `engine/array/driverWiring.ts`'s `combinedOfN`, `eachOfN`, `oneBoxOfN` and `driverDrive`, and air compliance in `engine/air.ts`'s `airCompliance`. A line whose every match lies inside its kind's home declaration is not a copy, so moving a sum into its home needs no list change; the same text anywhere else, code after the home's closing brace included, fails and names the home to call. A declared home must exist once and lie in `packages/design/engine/`. `scripts/dupscan-homes.json` and `scripts/dupscan.mjs` are gate files like the allow-list (`GATE_FILES` in `land.conf`), so a new home or a change to the check needs John's approval. The check compares the allow-list with the one on the base commit (`--base origin/main`) and the list only shrinks: a new entry, a raised count, a deleted entry, and a resolved entry made unresolved, replaced or rewritten (its `resolved_to`, `resolved_by` and `ruling` are history) all fail. The one exception is help text (QO950): a new entry whose reason starts "help text, no code" is accepted only when every match on its line lies inside a string or a comment, never for code and never for a jscpd copy. Keys leave comments out and keep literals exactly (strings, templates and regular expressions read by the TypeScript parser), so rewording a comment keeps a key. An entry re-keyed when a key's form changes names its old key in `"was"`: an unresolved base entry of the same rule and file (a copy: the same two files), claimed by that one entry, with no higher count. T934 took the open entries from 248 to 207: 41 marked resolved, 25 because the copy now calls the engine (`combinedOfN`, `eachOfN`, `oneBoxOfN`, `airCompliance`, `perCoilResistanceFactor`, and `boxes/port.ts`'s `tunedChamber` for the band-pass chambers) and 16 because the line already was its kind's home; 73 entries were re-keyed with `"was"` when the key form changed.
